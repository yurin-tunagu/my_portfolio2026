# 作業ログ：AIマンガ画像生成〜サイト組み込みプロセス

> 目的：後日、別のAIセッションに読み込ませて「マンガ画像生成〜サイト組み込み」の手順書（スキル）を生成するための素材。
> 対象プロジェクト：つなぐスタジオ・ポートフォリオ（イベント版）内の3話のマンガコンテンツ制作。

---

## 1. 目的と前提

### 1.1 何を実現する作業か
- 静的HTML/CSSサイト（つなぐスタジオ・ポートフォリオ、ビルドツールなし・手書きHTML）内に、3話のマンガ（悩み→AI活用→解決、の3コママンガ形式）を掲載する。
- 各話は「代表的な悩み」を1シーン（数コマ）ずつ複数ページ（画像）に分割し、スマホでも読めるページ送り形式で表示する。
- マンガの絵はClaude Codeでは生成できないため、**ChatGPT（GPT Image 2）で外部生成**し、生成された画像をダウンロード→レビュー→加工→サイトに配置、という一連の流れをAI（Claude Code）が支援する。

### 1.2 対象の3話
| ID | タイトル | 主人公設定 |
|---|---|---|
| 1-3 | 閉店後の「また明日」 | 40代男性・カフェ店主 |
| 2-1 | 毎月変わる、あの請求書 | 40〜50代男性・従業員5名程度の製造/卸小規模企業「代表」 |
| 3-3 | また、この質問 | 30〜40代女性・サロン「店長」 |

各話に共通して、ゆりん（サービス提供者）が後ろ姿のみ・顔非表示でパソコンを差し出す1コマが登場する（明るい茶色ミディアムボブ、ソフトピンクの服）。

### 1.3 環境・前提条件
- サイトはローカル未公開（git管理なし、GitHub push・Vercelデプロイともに**ユーザーの明示承認なしに実行しない**という制約が最上位）。
- 画像生成はChatGPT（GPT Image 2）を人間がブラウザ操作、生成物は `/Users/yurin/Downloads/<story-id>/` にダウンロードされる。
- Claude Codeの役割は「プロンプト作成・修正」「生成画像のレビュー」「サイトへの組み込みと検証」であり、画像生成そのものは行わない。
- サイト側の必須ルール（`AGENTS.md`/`CLAUDE.md`）：
  - HTML/CSS/JS変更後は必ず `python3 scripts/check_consistency.py` を実行
  - CSS/JS編集後は必ず `python3 scripts/bump_asset_version.py <name>` で全12ページの `?v=` キャッシュバスターを更新
- 画像仕様：1536×1024px（3:2横長）、PNGで生成→JPEG品質90に変換してサイトに配置。

## 2. 実行したプロセス（ステップバイステップ）

### Step 1: 画像生成プロンプトの作成
- 各話ごとに「共通ルール（毎回必ず入れる文言）」＋「話固有の指示」の2段構成でプロンプトを作成。
- 共通ルールの内容（`_修正指示のひな形.md` に集約）：
  - パソコンの向き：画面は登場人物のほうを向ける（カメラ・構図の工夫で対応、物理的にデバイスを回転させない）
  - 吹き出し：話者名（「AI画面」「代表」等のラベル）は描き込まない、セリフのみ
  - 手と機器：指示なきタッチ操作・浮遊オブジェクトを禁止。「手をキーボードの上に自然に置いている」という表現を使う（「トラックパッド操作」という表現は誤解を生むため使わない）
  - 人物：指示していない人物を画面に残さない
- プロンプトは「後半に書いた指示ほど強く効く」傾向があるため、**共通ルールを先頭、話固有の修正指示を末尾**に配置する構成にした。

### Step 2: 生成・ダウンロード・初回レビュー
- ユーザーがChatGPTで画像を生成し、`/Users/yurin/Downloads/<story-id>/` に保存。
- Claude Codeが画像を読み込み、以下の観点で欠陥を洗い出す：
  - パソコン画面の向き（読者側を向いていないか）
  - 吹き出し内の話者ラベルの有無
  - 手や機器の不自然さ（切断された手、ありえないジェスチャー、物体が画面から浮き出ている等）
  - AIチャット画面に存在しないはずのUIボタンが描かれていないか
  - 指示していない人物の写り込み
  - コマ間・ページ間の背景・小物（電話、書類、観葉植物、コーヒーカップ等）の一貫性
  - ページ間の色味・トーンの一貫性（特に別々に生成した複数ページ間で顕著）

### Step 3: 修正指示の作成・再生成（複数話・複数ラウンド）
- レビューで見つかった不具合を、話ごと・コマごとに整理してプロンプト化。
- 例（2-1・1回目の修正）：カレンダーの向き修正、支払日マーカーを1つに絞る、パソコン画面の異常な伸長を「物理的に妥当なサイズ」に修正、オフィスらしさ強化（コーヒーカップ全削除、観葉植物を最大1つに、ファイルボックス・バインダー・電話・書類トレイなどのオフィス小物追加）。
- 例（3-3・修正）：チェックマークの位置を「駐車場」に修正、壁のメモを削除、ゆりんが登場すべきでないコマから削除、電子機器を減らす。

### Step 4: サイトへの組み込み
1. `scripts/build_comic_pages.py` の `STORIES` 辞書に、話ごとのページ構成（何コマ目〜何コマ目がどのページ画像に対応するか、ラベルとalt用の説明文）を定義。
2. 生成されたPNG画像を `sips` コマンドでJPEG品質90に変換：
   ```bash
   sips -s format jpeg -s formatOptions 90 input.png --out output.jpg
   ```
   （約3MB → 約700〜820KBに圧縮）
3. 変換した画像を `assets/images/stories/<slug>/page-N.jpg` に配置。
4. `python3 scripts/build_comic_pages.py` を実行し、`<div class="comic-pages">` のHTMLブロックを自動生成・差し替え。
5. `python3 scripts/bump_asset_version.py <name>` でキャッシュバスターを更新。
6. `python3 scripts/check_consistency.py` でサイト全体の整合性を検証。
7. ローカルサーバー（`python3 -m http.server 4174`、`http://127.0.0.1:4174/` でアクセス。`file://` は相対リンクが壊れるため使用不可）でブラウザ表示を確認。
8. DOM検証（画像数、壊れた画像の有無、表示幅、コマ間の隙間、横スクロールの有無）をモバイル幅（375px）・デスクトップ幅（1024px）の両方でチェック。

### Step 5: 単一ページのみの再修正（部分修正パターン）
- 複数ページ生成後に「1ページだけ色味がおかしい」等の局所的な不具合が見つかった場合の専用フロー：
  1. 正しいトーンの隣接ページ（例：page-4.jpg）を「お手本」として添付
  2. プロンプト冒頭で「今回作ってほしいのは画像1枚だけ」「他のページは絶対に触らないでください」と明記
  3. 共通ルールのひな形ブロックは**あえて省略**
  4. セリフ・構図は「変えないでください」と明記し、一字一句を再掲
  5. 生成後、その1枚だけをレビュー→OKなら該当ファイルのみ差し替え→Step 4のパイプラインを再実行

## 3. 発生したエラーと解決策（最重要）

### 3.1 修正のたびに前回決めたルールが失われる
- **問題**：ChatGPTとの複数ターンのやり取り（「これも直して」の繰り返し）で、以前の指示（パソコン画面の向き等）が徐々に無視されるようになり、同じ不具合が別のコマ・別の話で再発した。
- **原因**：フォローアップ的な短い修正依頼だけでは、AIが会話の初期に設定したルールセットを保持しきれない。
- **解決策**：毎回の修正依頼の**冒頭に**共通ルールブロック（`_修正指示のひな形.md`）を必ず再掲し、話固有の指示はその**後に**続ける、というテンプレート運用を確立した。「後で読んだ指示ほど強く効く」という経験則に基づき、共通ルール→固有指示の順で配置。

### 3.2 単一ページ修正で共通ルールブロックを使うと逆効果
- **問題**：2-1のページ5（コマ9・10）のみ色味がずれていた事案で、当初は3.1の「共通ルールを毎回再掲」パターンをそのまま適用しようとしたが、ユーザーから「このボリュームの指示だと5枚（全ページ）生成されそうに見える」と指摘された。
- **原因**：長い共通ルール＋複数コマの言及を含むプロンプトは、AIに「全体を作り直すタスク」だと誤解させるリスクがある。
- **解決策**：範囲が1枚だけの修正では、
  - 冒頭に「画像1枚だけ」「他のページは触らない」と明記
  - 長いルールブロックの代わりに、**正しい色味の隣接ページ画像を添付して「これと同じ色味にして」と指示**
  - セリフは一字一句再掲して変更されないようにする
  という、テキストルール依存ではなく参照画像依存の短いプロンプトに切り替えた。これにより意図しない過剰生成を防いだ。

### 3.3 パソコンの画面がキャラクターではなく読者側を向いてしまう（再発型の不具合）
- **問題**：2-1のコマ2・3・4、3-3のコマ10など、複数の話・複数のコマで繰り返し発生。
- **原因**：AIが「画面の中身を見せたい」という一般的な構図の癖を持っており、明示的に指示しないと読者側に画面を向けてしまう。
- **解決策**：「画面は登場人物のほうを向けたまま、肩越しの構図で描く」という表現をルールに固定文言として組み込み、既に正しく描けている別コマ（例：3-3のコマ9）がある場合は「コマ9と同じ考え方で描いてください」と**成功事例を参照させる**指示が有効だった。

### 3.4 「トラックパッド」という表現が誤解を招いた
- **問題**：ノートパソコンの操作を「トラックパッド操作」と指示したところ、AIがありえないタッチジェスチャー（画面から物が飛び出す等）を描いてしまった。
- **解決策**：表現を「手をキーボードの上に自然に置いている姿で描いてください」という、動作を限定しない曖昧さの少ない表現に変更した。

### 3.5 話者ラベルが吹き出しに描き込まれる
- **問題**：「AI画面」「代表」などの話者名がセリフと一緒に画像内に描き込まれてしまう。
- **解決策**：「話者名は画像に描き込まないでください。セリフのみを吹き出しに入れてください」という文言を共通ルールに固定化した。

### 3.6 使わなくなった画像ファイルの混入
- **問題**：3-3のフォルダに `page-5.jpg` という、実際のHTML構成（4ページ構成）では参照されていないファイルが残っていた（過去の草稿の名残）。
- **解決策**：削除はせず `/tmp/unused-images/mata-kono-shitsumon_page-5.jpg` へ退避し、混乱を防止。**不要ファイルは即削除せず退避する**、というワークスペース共通ルールに従った対応。

### 3.7 見た目のギャップ・コマ間キャプションの雑多さ
- **問題**：各ページ画像の下に個別キャプションを表示すると、連続して読む際に視線の流れが分断される。
- **解決策**：`.comic-pages { gap: 0; }` でページ間の余白をゼロにし、視覚的なキャプションは廃止。代わりにアクセシビリティのため `aria-label`（ズームリンクの `<a class="comic-page__zoom">` に付与）に説明文を移動した。

### 3.8 モバイルでの文字の可読性不足
- **問題**：スマホ表示幅（約335px）では、元画像内のセリフ文字（約42px相当）が約9pxまで縮小され、読めなくなる。
- **解決策**：各ページ画像を `target="_blank" rel="noopener noreferrer"` のリンクで包み、フルサイズJPEGへ直接遷移できるズーム/ライトボックス的な導線を追加した。

## 4. 最終的な成功パターン・コード・設定値

### 4.1 プロンプトの型（複数コマ・広範囲修正時）
```
【毎回必ず入れる文言】
- パソコンの向き：画面は登場人物のほうを向けたまま、肩越しの構図で描いてください
- 吹き出し：話者名は描き込まず、セリフ本文のみにしてください
- 手と機器：手はキーボードの上に自然に置いている姿で描いてください。指示していない操作・浮遊するオブジェクトは描かないでください
- 人物：指示していない人物を画面に残さないでください
- セリフ：一字一句変更しないでください

【今回直したいコマと理由】
（話固有の具体的な指摘を、コマ番号ごとに列挙）
```

### 4.2 プロンプトの型（単一ページのみの修正時）
```
【最初に必ず読んでください】
今回作っていただきたいのは、画像1枚だけです。
すでにある〇枚のうち、コマ〇・〇が入った〇枚目だけを作り直してください。
他のページは完成しているので、絶対に触らないでください。
新しくセット全体を作り直す必要はありません。

# 直したい理由
添付した画像（〇枚目・コマ〇〇）をお手本にしてください。
（差分の具体的な説明：色味・トーンなど）

# 内容（変えないでください）
（場面・構図・セリフを一字一句再掲）

出来上がったら、この1枚だけを見せてください。
```

### 4.3 画像変換コマンド
```bash
sips -s format jpeg -s formatOptions 90 input.png --out output.jpg
```

### 4.4 サイト組み込みパイプライン（毎回同じ順序で実行）
```bash
python3 scripts/build_comic_pages.py
python3 scripts/bump_asset_version.py <変更内容を表す短い名前>
python3 scripts/check_consistency.py
python3 -m http.server 4174   # 別ターミナルで起動し http://127.0.0.1:4174/ で確認
```

### 4.5 `build_comic_pages.py` のページ構成定義パターン
```python
STORIES = {
    "<slug>": {
        "title": "<話タイトル>",
        "pages": [
            ("第N〜Mコマ", "<場面説明。alt属性・aria-labelの元テキストになる>"),
            # ページ数分繰り返す（1話あたり3〜5ページ）
        ],
    },
}
```
- 1ページ＝1画像＝1536×1024pxのJPEG。ファイル名は `page-1.jpg`, `page-2.jpg`...の連番。
- `build_html()` が各ページを次の形に自動生成：
  ```html
  <figure class="comic-page">
    <a class="comic-page__zoom" href="{src}" target="_blank" rel="noopener noreferrer"
       aria-label="{label}を拡大して見る（画像を新しいタブで開きます）">
      <img src="{src}" width="1536" height="1024" loading="lazy" decoding="async"
           alt="{label}。{desc}" />
    </a>
  </figure>
  ```

### 4.6 CSS要点
```css
.comic-pages { gap: 0; } /* ページ間の視覚的な隙間をなくし、縦スクロールで連続して読める体験にする */
```

### 4.7 運用ルール（今回確立した知見のまとめ）
| 状況 | 取るべきプロンプト戦略 |
|---|---|
| 複数コマ・複数話にまたがる修正 | 共通ルールを先頭に毎回フル再掲＋話固有指示を末尾に追加 |
| 1ページのみの局所修正 | 共通ルールは省略し「1枚だけ」明記＋正しい色味/構図の参照画像を添付＋セリフ一字一句再掲 |
| 同じ不具合が繰り返し発生するコマ | 同一シート内の「正しく描けている別コマ」を名指しして「そのコマと同じ考え方で」と参照させる |
| 使われなくなった生成物 | 削除せず `/tmp/` 等へ退避、HTMLから参照されていないことを確認してから判断 |
